## What was tested

A production build (`next build` and `next start`) against the dev database, with email switched off. Every run used throwaway `@example.invalid` accounts, deleted afterwards.

- **Automated gates:** type-check, lint (whole repo), unit, integration (real database), the Python runner suite, content validation (every drill's reference solution and every runnable example), the dependency audit, the production build, and the Playwright suite.
- **Exploratory pass** (`.impeccable/qa-explore.mjs`, 47 checks):
  - the public HTTP surface: public pages, 404s, security headers, robots and sitemap;
  - every protected API refusing signed-out callers, and a learner refused by every admin route;
  - sign-up through the real form, onboarding, running a lesson example, passing a drill;
  - review, log, achievements, profile, syllabus, settings and search;
  - the name rules and the password policy in Settings;
  - an AI key stored as a hint only;
  - sign-out clearing the browser, the old password refused after a change;
  - deleting the account from Settings.
- **Regression scripts:**
  - the full first-session quest (a beginner, a developer who skips and resumes, an existing learner, a phone);
  - the beginner on-ramp through the white-belt ceremony and its badges;
  - the admin area;
  - the belt test-out with its late-night warning, the learning log, and the Python certificate by its real rule;
  - the landing page's sandbox and its two ways in;
  - draft isolation between two accounts on one browser;
  - the password policy and the four stages of the bug-fix quest step;
  - the tutor's waiting lines.
- **Accessibility audit:** axe (WCAG 2.2 AA) and horizontal overflow on every main surface, desktop and phone, light and dark, learner and admin.
- **Security re-check:** every finding in the security report re-verified against the code, a guard table for all 58 API routes, and an import-graph scan for secrets reaching the browser bundle.

## Bugs found and fixed in this pass

1. **A suspended admin could still download learners' submitted files.** That route had its own sign-in check that skipped the suspension check. It now uses the shared admin guard.
2. **"I already code" didn't undo an earlier "I've never coded"** on the same browser, so onboarding pre-selected "New to programming" for a developer. It now clears it.
3. **The profile, a capstone page and the examiner's queue called the site's own API over HTTP**, forwarding the cookie and building the URL from the Host header (security finding M-4). They now read the data directly. The profile's queries also run in parallel now, which took it from 7.3 s to about 2.6 s.
4. **Four admin pages showed another page's loading screen.** Activity, Notifications, Users and a user's record now have their own.
5. **The launch docs told you to switch on server grading**, which isn't safe yet (finding C-2). `WHATS-LEFT.md`, `DEPLOYMENT.md` and `ARCHITECTURE.md` now say to keep it on `client`.

## Security

Details are in [security_best_practices_report.md](../security_best_practices_report.md), "Status on 2026-10-19". In this pass:

- **Dependencies upgraded** (C-3): `next` 16.3.8, `next-auth` 5.0.0-beta.32, `@auth/prisma-adapter` 2.11.3, `nodemailer` 10.0.15. `shadcn` moved to devDependencies. CI now fails on any critical advisory.
- **Startup check:** in production the server refuses to start with `GRADING_MODE=server`, and logs each missing launch setting (Upstash, email, `ENCRYPTION_KEY`, `CONTACT_EMAIL`, `ADMIN_BOOTSTRAP_EMAIL`).
- **Sign-in is limited per IP** as well as per account.
- **GitHub sign-ins need an address GitHub has verified**, as Google sign-ins already did.
- **One-time links can't be used twice in a race.**
- **Examiner downloads are always inert files** (`application/octet-stream`, sandboxed, safe filename).
- **Self-fetches over HTTP are gone** (M-4).

## Decision needed before launch

**Drill grading is honour-system in v1.** Drills and gradings are checked in the learner's browser, so someone who forges a request can mark them passed. That moves rank and the black belt's grading rule. Capstones are approved by an examiner, so a certificate still needs a person's sign-off. Fixing it properly means running learner code in a sandbox (v2, M9). Recommendation: launch with it, and say so plainly if anyone asks how grading works.

## Known, accepted for v1

- **Sessions survive a password change** for up to their 30 days (M-2). This is the first security follow-up after launch.
- **Sign-up says when an email already has an account** (L-8). That's a usability trade-off; OWASP prefers one answer for every address.
- **Low-severity items L-2, L-4, L-6, L-7 and L-9** (see the security report).
- **The Python interpreter's rare stack overflow** during very long runs is caught, and the run is retried on a fresh worker, so learners don't see it.
- **The landing page is long on phones** (about 10,600 px).

```bash
npx tsc --noEmit && npx eslint . && npm test && npm run test:integration && npm run test:python
npm run content:validate
NEXT_DIST_DIR=.next-e2e AUTH_URL=http://localhost:3010 npm run build
NEXT_DIST_DIR=.next-e2e npx playwright test

# Against the running build on :3010
BASE=http://localhost:3010 node .impeccable/qa-explore.mjs
BASE=http://localhost:3010 node .impeccable/app-audit.mjs
# plus quest-e2e, onramp-e2e, admin-e2e, today-e2e, landing-e2e, verify-drafts, verify-auth-quest, tutor-wait-e2e
```
